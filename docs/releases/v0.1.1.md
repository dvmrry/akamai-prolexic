# prolexic v0.1.1

## Fixed

- **A BGP session without a usable AS number now stops the plan.** The own-space check takes our own AS numbers from the BGP sessions in Prolexic Analytics. A session whose `asn` was missing or out of range was left out silently, so a deny `ASN::` entry for that AS would have passed the check. The plan now fails with `own_space_unreadable`, as it already does for a protected subnet it can't read. `prolexic protected` counts such sessions in `unusableASNs` and notes them. `--no-analytics-own-space` still skips the Analytics checks, and the plan records that it did.
